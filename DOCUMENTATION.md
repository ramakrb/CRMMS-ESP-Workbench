# CRMMS ESP Preset Plots & Parquet Data Pipeline

## 1. Project Overview & Architecture

This application is a **serverless, client-side web application** hosted on **GitHub Pages**. It visualizes monthly ensemble forecast outputs generated by the Bureau of Reclamation's **CRMMS** (Colorado River Mid-Term Operations Model) RiverWare models.

Historically, CRMMS outputs are exported in RiverWare Data Format (`.rdf`) files. This project converts those multi-file monthly outputs into high-performance, compressed **Apache Parquet (`.parquet`)** files and renders preset plots, percentiles (Min, 10%, Most Probable, 90%, Max), and data tables using **hyparquet** and **Plotly.js** directly inside the user's web browser.

## 3. The Parquet Data Model

### Why Parquet?
- **Extreme Compression**: Raw `.rdf` files for a single monthly run exceed 3 MB of uncompressed text (> 265,000 lines). The equivalent Parquet file with Snappy compression is only **~0.6 MB** (~80% smaller).
- **Fast Load Times**: Instead of downloading megabytes of text and parsing line-by-line in JavaScript on startup, the browser loads binary Parquet in a few milliseconds.
- **GitHub Pages Scale**: 10 years of monthly model runs (120 months) take **~70 MB to 80 MB total**, staying comfortably under GitHub’s 1 GB repository recommendation.

### Schema Specification
Every `.parquet` file in `data/runs/` contains a normalized long-format table:

| Column Name | Arrow / Parquet Type | Pandas Type | Description |
| :--- | :--- | :--- | :--- |
| `period_date` | `string` (`YYYY-MM-DD`) | `object` / `string` | Observation date (e.g. `2026-07-31` or annual `2026-12-31`) |
| `year` | `int16` | `int16` | Calendar / water year |
| `month` | `int8` | `Int8` (nullable) | Month (1–12, or `null` for annual slots) |
| `timestep_type`| `dictionary<string>` | `category` | `monthly` or `annual` |
| `trace_number` | `int16` | `int16` | RiverWare trace number (e.g. 2, 3, 4 ... 33) |
| `esp_year` | `int16` | `Int16` (nullable) | Historical ESP year (trace 4 = 1991 ... trace 33 = 2020) |
| `object_name` | `dictionary<string>` | `category` | RiverWare object (e.g. `Powell`, `Mead`, `BlueMesa`) |
| `slot_name` | `dictionary<string>` | `category` | RiverWare slot (e.g. `Pool Elevation`, `Outflow`, `Energy`) |
| `object_slot` | `dictionary<string>` | `category` | Fully qualified `Object.Slot` (e.g. `Powell.Pool Elevation`) |
| `unit` | `dictionary<string>` | `category` | Engineering unit (e.g. `ft`, `acre-ft`, `NONE`) |
| `value` | `float32` | `float32` | Scaled numeric value (`raw_value * scale`) |
| `rdf_source` | `dictionary<string>` | `category` | Source filename without extension (e.g. `res`, `flags`, `streamflow`) |
| `model_run_month` | `dictionary<string>` | `category` | Run identifier in `YYYY-MM` format (e.g. `2026-07`) |

## 4. How to Create a New Parquet File Every Month

Whenever a new monthly RiverWare run is generated:

### Prerequisites (Python Environment)
```bash
pip install pandas pyarrow
```

### Monthly Execution
1. Place the month's `.rdf` files (e.g. `res.rdf`, `flags.rdf`, `streamflow.rdf`) into a folder, e.g. `raw_inputs/2026-08/` or directly in `data/`.
2. Run `convert_to_parquet.py`:
   ```bash
   python convert_to_parquet.py --input-dir data --output-file data/runs/2026-08.parquet --month 2026-08
   ```
3. What the script does automatically:
   - Reads every `.rdf` file found in `--input-dir`.
   - Scales numeric values by RiverWare's `scale` parameter.
   - Computes `esp_year` (1987 + trace) for traces 4–33.
   - Encodes string columns as dictionaries for high compression.
   - Writes `data/runs/2026-08.parquet` using Snappy compression.
   - Automatically rescans `data/runs/` and regenerates `data/runs/catalog.json`.

## 5. Adding More `.rdf` Files (Monthly or Annual)

If future CRMMS runs include additional `.rdf` files (e.g., `salinity.rdf`, `demands.rdf`, `hydropower.rdf`, or new annual shortage tables):

1. **Zero Code Changes Required**:
   - `convert_to_parquet.py` uses `input_dir.glob("*.rdf")`. It does not hardcode `res`, `flags`, or `streamflow`.
   - Simply drop the new `.rdf` file into the folder alongside the other files.
2. **Automatic Schema Adaptation**:
   - The script automatically detects the timestep (`monthly`, `annual`, `daily`), unit, and scale from the `.rdf` headers.
   - The source filename is stored under `rdf_source` (e.g. `rdf_source = 'salinity'`).
3. **Frontend Discovery**:
   - In the web app, any new slot (e.g. `Salinity.Concentration`) will automatically appear in:
     - The **Data Table** slot dropdown (`#dtSlot`).
     - The **Add Plot** picker (`#addSlot`).
     - Any new preset configured in `index.html` under `PRESETS` or `RESERVOIR_PAGES`.

## 6. How the Frontend Works (Runtime Pipeline)

1. **Page Load**:
   - `bootstrap.js` executes `boot()`.
   - `dashboard.js` fetches `data/runs/catalog.json` and renders the **Historical Runs** dashboard.
   - Months without data (`available: false`) are hidden from the user.
   - The preset buttons (*Powell + Mead Elevations*, *Powell Inflow PE*, etc.) and top back button remain hidden until a run is selected.
2. **User Selects a Month**:
   - Clicking a month tile triggers `loadMonthRun('2026-07', 'data/runs/2026-07.parquet')`.
   - `parquet-reader.js` reads the file buffer using `hyparquet.esm.js`.
   - The data is shaped into RiverWare `slots -> traces -> points` maps.
   - `loadData([parsedFile])` is called, populating `model` and initializing Plotly charts.
   - The top header displays:
     - **`← Historical Runs`** (left of the badge, aligned and sized identically).
     - **`Model run: Month YYYY`** (dynamically updated to the loaded run).
   - The preset buttons (*Powell + Mead Elevations*, *Reservoir Charts*, *Tables*) are shown.
3. **Navigating Back**:
   - Clicking **`← Historical Runs`** calls `showDashboardView()`.
   - The plot grid and preset bar are hidden, and the multi-month selector is redisplayed.

## 7. Migration Guide: Running on a New Machine

To set up and run this project on another machine:

### 1. Clone the Repository
```bash
git clone https://github.com/bramakrishnan-doi/crmms-esp-workbench.git
cd crmms-esp-workbench
git checkout feature/parquet-dashboard
```

### 2. Local Testing (No Node or Build Step Required)
Because the app uses pure ES modules and client-side JavaScript, simply start any static HTTP server:
```bash
# Using Python:
python -m http.server 8000

# Or using Node:
npx serve .
```
Open `http://localhost:8000` in your browser.

### 3. Deploying to GitHub Pages
1. Push `feature/parquet-dashboard` to GitHub:
   ```bash
   git push -u origin feature/parquet-dashboard
   ```
2. In GitHub repository settings:
   - Navigate to **Settings** → **Pages**.
   - Under **Build and deployment** → **Branch**, select `feature/parquet-dashboard` and folder `/ (root)`.
   - Save. Your application will be live at `https://<username>.github.io/<repo>/`.
